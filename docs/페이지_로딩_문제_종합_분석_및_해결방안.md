# 페이지 로딩 문제 종합 분석 및 해결방안

## 🔴 핵심 문제

**사용자 요구사항:**
> "복잡한 외부 기능 사용 안하고, 각 페이지의 컨텐츠가 추가적 효과 없이 그냥 바로 정상적으로 표시되는 것"

**현재 상황:**
- 모든 페이지에 fullpage.js, slick.js, swiper.js, AOS 등 복잡한 라이브러리 로드
- 이러한 라이브러리들이 페이지 콘텐츠 표시를 **방해**하고 있음
- 콘솔 에러가 지속적으로 발생

---

## 📊 콘솔 에러 상세 분석

### 1. fullpage_min.css 404 에러
```
GET https://www.mekeng.com/public/css/fullpage_min.css?ver=25103108 
net::ERR_ABORTED 404 (Not Found)
```
**원인:** 파일 경로 문제 또는 파일 누락
**영향:** fullpage.js가 제대로 작동하지 않음

### 2. jQuery Syntax 에러
```
jquery-3.7.0.min.js?ver=220620:2 Uncaught SyntaxError: Unexpected token '&'
```
**원인:** jQuery 파일 자체가 손상되었거나 잘못된 버전
**영향:** 모든 jQuery 기반 스크립트 작동 불가

### 3. dxee.common.js 에러
```
dxee.common.js?ver=220620:40 Uncaught ReferenceError: tabActive is not defined
```
**원인:** `dxee.common.js`에서 정의되지 않은 함수 호출
**코드 위치:**
```javascript
// dxee.common.js:40
$(siteLoad)
  .on('click', '.tab a', tabActive)  // ← tabActive 함수가 정의되지 않음
  .on('click', '.mobile-menu', mobileMenuToggle)  // ← 이것도 정의 안됨
```

### 4. fullpage.js 라이선스 경고
```
fullPage: Fullpage.js version 3 has changed its license to GPLv3 
and it requires a `licenseKey` option.
```
**원인:** fullpage.js v3는 상업용 라이선스 필요
**현재 설정:** `licenseKey: 'DXEE'` (무효한 키)

### 5. fullpage.js 확장 에러
```
fullPage: fullpage.js extensions require fullpage.extensions.min.js 
file instead of the usual fullpage.js. Requested: scrollHorizontally
```
**원인:** `scrollHorizontally` 옵션은 유료 확장 기능
**현재 설정:** 무료 버전으로는 사용 불가

### 6. slick.js 에러
```
slick.js:1307 Uncaught TypeError: Cannot read properties of null (reading 'add')
```
**원인:** slick.js가 존재하지 않는 DOM 요소에 접근 시도
**영향:** 슬라이더 작동 불가

## 🎯 근본 원인 분석

### 문제 1: AOS가 콘텐츠를 숨김
**AOS의 작동 방식:**
```css
/* aos.css */
[data-aos^=fade][data-aos^=fade] {
    opacity: 0;  /* ← 기본적으로 숨김 */
    transition-property: opacity, transform;
}

[data-aos=fade-up] {
    transform: translate3d(0, 100px, 0);  /* ← 아래로 이동 */
}

/* AOS.init()이 실행되면 */
[data-aos^=fade][data-aos^=fade].aos-animate {
    opacity: 1;  /* ← 보이게 함 */
    transform: translateZ(0);
}
```

**문제점:**
1. 페이지의 모든 콘텐츠에 `data-aos="fade-up"` 속성 적용
2. AOS.js가 로드되기 전까지 **모든 콘텐츠가 숨겨짐** (`opacity: 0`)
3. AOS.js에 에러가 있거나 로드 실패 시 → **페이지가 빈 화면으로 표시**

### 문제 2: 복잡한 라이브러리 의존성
```
페이지 로드 순서:
1. jQuery 1.12.4 로드
2. jQuery 3.7.0 로드 (충돌 가능성)
3. jQuery Migrate 로드
4. dxee.common.js 로드 → fullPageInit() 실행 시도
5. fullpage.js 로드 → 라이선스 에러
6. swiper.js 로드 → DOM 요소 찾기 시도
7. slick.js 로드 → null 에러
8. AOS.js 로드 → 콘텐츠 표시
```

**문제점:**
- 8단계를 모두 성공해야 페이지가 정상 표시
- 하나라도 실패하면 → 콘텐츠 표시 안됨

### 문제 3: 메인 페이지 전용 기능을 모든 페이지에 로드
- **fullpage.js**: 메인 페이지의 `#fullpage` 요소에만 필요
- **swiper.js**: 메인 페이지의 비주얼 슬라이더에만 필요
- **slick.js**: 메인 페이지의 파트너/인증서 슬라이더에만 필요
- **서브 페이지**: 이런 기능들이 전혀 필요 없음

### 방안 1: 모든 애니메이션 효과 제거 (권장 ⭐⭐⭐⭐⭐)

**목표:** 페이지 콘텐츠가 즉시, 확실하게 표시되도록

#### 1-1. AOS 완전 제거
```php

// add_javascript('<script src="'.G5_JS_URL.'/aos.js"></script>', 0);
// add_stylesheet('<link rel="stylesheet" href="'.G5_CSS_URL.'/aos.css">', 0);
```

#### 1-2. PHP 파일에서 data-aos 속성 제거

#### 1-3. 메인 페이지 전용 스크립트만 조건부 로드

#### 1-4. dxee.common.js 수정
```javascript
// dxee.common.js - 함수 정의 추가
function tabActive(e) {
    e.preventDefault();
    var $tab = $(this);
    $tab.closest('.tab').find('a').removeClass('active');
    $tab.addClass('active');
    var target = $tab.attr('href') || $tab.data('target');
    if (target) {
        $tab.closest('.tab').siblings('.tab-content').hide();
        $(target).show();
    }
}

function mobileMenuToggle(e) {
    e.preventDefault();
    $('.mobile-menu').toggleClass('active');
    $('#sitemap').slideToggle();
}

function sticky() {
    if ($(window).scrollTop() > 100) {
        $('#header').addClass('sticky');
    } else {
        $('#header').removeClass('sticky');
    }
}

// 이벤트 등록 (안전하게)
$(siteLoad);

$(document).on('click', '.tab a', tabActive);
$(document).on('click', '.mobile-menu', mobileMenuToggle);
$(window).on('scroll', sticky);
```

### 방안 2: 최소한의 AOS만 유지 (중간 단계)

#### 2-1. CSS 폴백 강화
```css
/* style.css에 추가 */
/* AOS 폴백: 기본적으로 모든 콘텐츠 표시 */
[data-aos] {
    opacity: 1 !important;
    transform: none !important;
    visibility: visible !important;
    transition: none !important;
}

/* AOS가 정상 로드된 경우에만 애니메이션 활성화 */
html.aos-initialized [data-aos] {
    opacity: 0;
    transition: opacity 0.3s ease, transform 0.3s ease;
}

html.aos-initialized [data-aos].aos-animate {
    opacity: 1;
    transform: none;
}
```

#### 2-2. script.js 수정
```javascript
$(function() {
    // AOS 초기화 (실패해도 콘텐츠는 표시됨)
    try {
        if (typeof AOS !== 'undefined') {
            AOS.init({
                duration: 300,  // 짧게
                once: true,     // 한 번만
                offset: 0,      // 즉시
                disable: function() {
                    // 모바일이나 느린 네트워크에서는 AOS 비활성화
                    return window.innerWidth < 768 || 
                           navigator.connection && 
                           navigator.connection.effectiveType === '2g';
                }
            });
            document.documentElement.classList.add('aos-initialized');
        }
    } catch(e) {
        console.warn('AOS initialization failed:', e);
        // 에러 발생해도 콘텐츠는 표시됨 (CSS 폴백)
    }
});
```

## 💡 결론

**현재 문제의 핵심:**
- 복잡한 애니메이션 라이브러리들이 페이지 콘텐츠 표시를 **차단**하고 있음
- 에러 발생 시 복구 메커니즘이 없어 빈 화면만 표시됨

**해결책:**
1. **모든 애니메이션 효과 제거** (가장 확실한 방법)
2. 페이지 콘텐츠를 즉시 표시
3. 필요한 경우에만 최소한의 효과 재적용

**예상 효과:**
- ✅ 모든 페이지가 즉시, 확실하게 표시
- ✅ 콘솔 에러 제거
- ✅ 페이지 로드 속도 향상 (약 50% 이상)
- ✅ 네트워크 환경이 좋지 않은 지역에서도 안정적 작동
- ✅ 유지보수 용이성 향상
