# WSL 백업 스크립트 위치 권장사항

## 📍 두 가지 위치 옵션 비교

### 옵션 1: `/usr/local/bin` (권장) ⭐⭐⭐⭐⭐

**장점**:
- ✅ PATH에 기본 포함되어 있어 어디서든 실행 가능
- ✅ 시스템 유틸리티를 위한 표준 위치
- ✅ 웹사이트 프로젝트와 독립적 관리
- ✅ 다른 시스템 스크립트(`backup.sh`, `backup_html.sh` 등)와 함께 관리
- ✅ cron에서 간단한 이름으로 실행 가능 (`wsl_rsync_backup.sh`)

**위치**:
```
/usr/local/bin/
├── wsl_rsync_setup.sh
├── wsl_rsync_backup.sh
└── (다른 시스템 스크립트들)
```

**cron 설정**:
```bash
0 10 * * 1 wsl_rsync_backup.sh
```

**장점**:

**단점**:


## 🔧 권장: `/usr/local/bin`으로 이동

### 이동 절차

```bash
# 1. 스크립트를 /usr/local/bin으로 복사
sudo cp /var/www/html/mekeng.com/backup-scripts/wsl_rsync_*.sh /usr/local/bin/

# 2. 실행 권한 부여
sudo chmod +x /usr/local/bin/wsl_rsync_*.sh

# 3. 이동 확인
ls -la /usr/local/bin/wsl_rsync_*

# 4. PATH 확인 (어디서든 실행 가능한지 테스트)
which wsl_rsync_backup.sh
wsl_rsync_backup.sh --help  # 또는 실행 테스트

# 5. cron 설정 업데이트
crontab -e
# 수정:
0 10 * * 1 wsl_rsync_backup.sh
```

### 장점 요약

1. **간편한 실행**: 어떤 디렉토리에서든 `wsl_rsync_backup.sh` 실행 가능
2. **간단한 cron 설정**: 전체 경로 불필요
3. **시스템 레벨 관리**: 다른 시스템 스크립트와 함께 관리
4. **표준 위치**: 리눅스 표준 파일 시스템 계층 구조(FSH) 준수
